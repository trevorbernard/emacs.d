* Introduction

I run Emacs =30.2= exclusively in the terminal (=emacs -nw=) on both
Linux and Mac. Startup speed matters. This configuration uses
=use-package= with global deferred loading and native compilation.

Remap Caps Lock to Control. Your pinkies will thank you.

** Installation

#+begin_example
git clone git@github.com:trevorbernard/emacs.d.git ~/.emacs.d
cd ~/.emacs.d
make setup
#+end_example

=make setup= installs all ELPA packages, downloads tree-sitter grammars,
and compiles the configuration. Requires Emacs 30+ (=use-package= with
=:vc= support).

Start Emacs with =emacs -nw=. After editing =configuration.org=, run =make=
to tangle and recompile.

* Bootstrap

Everything here runs before the main configuration loads. The GC
threshold is cranked up during init and restored at the [[*Epilogue][end]].

** Early Init

#+begin_src emacs-lisp :tangle early-init.el
  ;;; -*- lexical-binding: t -*-

  (setq process-adaptive-read-buffering nil
        read-process-output-max (* 10 1024 1024))

  (add-hook 'emacs-startup-hook
            (lambda ()
              (setq gc-cons-threshold 16777216
                    gc-cons-percentage 0.1)
              (message "Emacs ready in %s with %d garbage collections."
                       (format "%.2f seconds" (float-time (time-subtract after-init-time before-init-time)))
                       gcs-done)))

  (setq gc-cons-threshold most-positive-fixnum
        gc-cons-percentage 0.9)

  (set-face-attribute 'mode-line nil :background 'unspecified)
  (set-face-attribute 'header-line nil :background 'unspecified)

  (setq-default mode-line-format nil)

  (add-to-list 'custom-theme-load-path
               (expand-file-name "elpa/timu-spacegrey-theme" user-emacs-directory))
  (setq timu-spacegrey-transparent-background t)

  (menu-bar-mode -1)

  (defun display-startup-echo-area-message ())

  (setq inhibit-startup-message t)

  ;; A lisp-interaction-mode scratch buffer fires every prog-mode hook at
  ;; startup, dragging in corfu, yasnippet, and paredit (~70ms).
  ;; (setq initial-major-mode 'fundamental-mode)

  (when (native-comp-available-p)
    (startup-redirect-eln-cache (expand-file-name "eln-cache/" user-emacs-directory))
    (setq native-comp-speed 2
          native-comp-jit-compilation t
          native-comp-async-jobs-number (min 4 (max 1 (/ (num-processors) 2)))
          native-comp-async-report-warnings-errors nil))

  (setenv "LSP_USE_PLISTS" "true")

  ;; Bootstrap package system and use-package for better startup performance
  (require 'package)

  (setq package-archives '(("melpa" . "https://melpa.org/packages/")
                           ("melpa-stable" . "https://stable.melpa.org/packages/")
                           ("gnu" . "https://elpa.gnu.org/packages/")
                           ("nongnu" . "https://elpa.nongnu.org/nongnu/")))

  ;; pin to melpa-stable to avoid bleeding-edge breakage
  (setq package-pinned-packages
        '((projectile . "melpa-stable")
          (cider      . "melpa-stable")))

  (setq package-enable-at-startup nil
        package-quickstart t
        package-quickstart-file (expand-file-name "package-quickstart.el" user-emacs-directory))

  (package-activate-all)

  (setq use-package-always-defer t
        use-package-verbose nil)
  (require 'use-package)

  (provide 'early-init)

** Clipboard

Wayland needs explicit plumbing to share the clipboard with other
applications. Over SSH, OSC-52 escape sequences get yanked text to the
host clipboard instead.

=tb/wl-paste= calls =wl-paste= directly instead of through a shell.
The shell version captured stderr too, so an empty clipboard pasted
wl-paste's "No selection" message as text, and it spawned a shell and
a =tr= on every yank. An empty result returns nil so =current-kill=
falls back to the kill ring.

#+begin_src emacs-lisp
  (when (and (getenv "WAYLAND_DISPLAY") (executable-find "wl-copy"))
    (setq tb/wl-copy-process nil)
    (defun tb/wl-copy (text)
      (setq tb/wl-copy-process (make-process :name "wl-copy"
                                             :buffer nil
                                             :command '("wl-copy" "-f" "-n")
                                             :connection-type 'pipe
                                             :noquery t))
      (process-send-string tb/wl-copy-process text)
      (process-send-eof tb/wl-copy-process))
    (defun tb/wl-paste ()
      (unless (and tb/wl-copy-process (process-live-p tb/wl-copy-process))
        (with-temp-buffer
          (call-process "wl-paste" nil '(t nil) nil "-n")
          (unless (zerop (buffer-size))
            (string-replace "\r" "" (buffer-string))))))
    (setq interprogram-cut-function 'tb/wl-copy)
    (setq interprogram-paste-function 'tb/wl-paste))
#+end_src

Clipetty (OSC-52) covers the cases where wl-copy isn't around: SSH
sessions and local Mac. In a local Wayland session the wl-copy
plumbing above already owns the clipboard, so clipetty stays off and
=M-w= keeps its default =kill-ring-save=. Don't gate this on =SSH_TTY=
alone. That would also turn clipetty off in a local Mac terminal,
where OSC-52 is the only way to the pasteboard.

#+begin_src emacs-lisp
  (use-package clipetty
    :ensure t
    :if (or (getenv "SSH_TTY")
            (not (and (getenv "WAYLAND_DISPLAY") (executable-find "wl-copy"))))
    :bind ("M-w" . clipetty-kill-ring-save))
#+end_src

* Navigation & Completion

** Vertico, Orderless & Marginalia

Vertico enhances the built-in =completing-read= UI instead of
replacing it, so every command picks it up with no adapters. Vertico,
orderless, and marginalia load eagerly. Each is one small file, and
deferring them only bought a window where =M-x= had neither the UI nor
the matching style. Marginalia can't ride =vertico-mode-hook= either:
vertico-mode has already run by the time the hook gets installed.

Savehist is on regardless of the frontend. Minibuffer history is worth
keeping, and corfu-history reads the same store.

#+begin_src emacs-lisp
  (use-package vertico

    :demand t
    :config
    (vertico-mode 1))

  (use-package savehist
    :demand t
    :config
    (savehist-mode 1))

  (use-package marginalia
    :ensure t
    :demand t
    :config
    (marginalia-mode 1))

  (use-package orderless
    :ensure t
    :demand t
    :config
    (setq completion-styles '(orderless basic)
          completion-category-overrides '((file (styles basic partial-completion))
                                          (lsp-capf (styles orderless)))))
#+end_src

** Consult

Consult fills the holes counsel left: line search, buffer switching,
imenu, yank history, and grep. Keys follow the consult README.
=C-x b= and =M-y= are replaced outright, because consult's versions do
everything the built-ins do, plus preview. Search goes under =M-s=,
jumps under =M-g=.

xref goes through consult too, so =M-.= and =M-?= (lsp, CIDER, elisp)
show their matches in vertico with a preview. That's what lsp-ivy used
to do.

Projectile registers itself with =project.el=, so =consult-buffer='s
project sources and =consult-ripgrep= find the project root on their
own.

#+begin_src emacs-lisp
  (use-package consult
    :ensure t
    :bind (("C-x b"   . consult-buffer)
           ("C-x 4 b" . consult-buffer-other-window)
           ("M-y"     . consult-yank-pop)
           ("M-g g"   . consult-goto-line)
           ("M-g M-g" . consult-goto-line)
           ("M-g i"   . consult-imenu)
           ("M-s l"   . consult-line)
           ("M-s r"   . consult-ripgrep)
           ("M-s g"   . consult-git-grep))
    :init
    (setq xref-show-xrefs-function #'consult-xref
          xref-show-definitions-function #'consult-xref))
#+end_src

** Corfu

Corfu reads =completion-at-point-functions= directly. C-n/C-p and
M-</M-> work in the popup out of the box. TTY frames don't get child
frames until Emacs 31, so corfu-terminal (NonGNU ELPA) draws the popup
with overlays. It stands down by itself on graphical displays.
corfu-popupinfo is off for the same reason. It only shows beside a
child-frame popup, so under corfu-terminal it never appears. Bring it
back with Emacs 31.

Corfu runs in text and conf buffers too, not just prog-mode. That's
where the cape fallbacks below matter most. Emacs 30 adds an ispell
capf to =text-mode=, which would flood every popup with dictionary
words, so it's turned off.

Company bundled dabbrev and file-path backends. Corfu only reads capf,
so cape supplies those. They sit at low priority so a mode-specific
capf (elisp, LSP, CIDER) still wins, and buffers without one (YAML,
Markdown, Clojure without a REPL) still get something. Both capfs are
autoloaded, so hooking them in =:init= leaves cape unloaded until the
first completion.

#+begin_src emacs-lisp
  (use-package corfu
    :ensure t
    :custom
    (corfu-auto t)
    (corfu-cycle t)
    (text-mode-ispell-word-completion nil)
    :hook (((prog-mode text-mode conf-mode) . corfu-mode)
           (corfu-mode . corfu-history-mode)))

  (use-package corfu-terminal
    :ensure t
    :after corfu
    ;; :after alone never loads a deferred package; :demand makes the
    ;; corfu after-load actually require it.
    :demand t
    :config
    (corfu-terminal-mode 1))

  (use-package cape
    :ensure t
    :init
    (add-hook 'completion-at-point-functions #'cape-dabbrev 90)
    (add-hook 'completion-at-point-functions #'cape-file 90))
#+end_src

** Flycheck

Flycheck ships a =python-ruff= checker, so Python only needs the
buffer restricted to ruff. No custom checker needed.

flycheck-rust configures the =rust-cargo= checker from cargo metadata
so binary-only crates don't fail with "no library targets found". It
hooks =flycheck-mode=, not =rust-mode=: flycheck is deferred, so in
the first Rust buffer flycheck-rust loads during =rust-mode-hook= and
its own add-hook lands too late to run.

The mode guard matters because =flycheck-mode-hook= fires in every
checked buffer, and =flycheck-rust-setup= shells out to =cargo
metadata= whenever it finds a Cargo.toml above the file. Without it, a
Python or pest buffer inside a Rust project pays for a synchronous
cargo call. rustic-mode derives from rust-mode, which derives from
rust-ts-mode, so both names cover it.

#+begin_src emacs-lisp
  (defun tb/python-ruff-setup ()
    "Configure ruff as the Python checker unless in org-src-mode."
    (unless (bound-and-true-p org-src-mode)
      (when (buffer-file-name)
        (flycheck-mode)
        (setq-local flycheck-checkers '(python-ruff)))))

  (use-package flycheck
    :ensure t
    :hook ((python-ts-mode . tb/python-ruff-setup)
           (rust-mode . flycheck-mode))

    :bind (:map flycheck-mode-map
                ("M-n" . flycheck-next-error)
                ("M-p" . flycheck-previous-error)))

  (defun tb/flycheck-rust-setup-maybe ()
    "Run `flycheck-rust-setup' only in Rust buffers."
    (when (derived-mode-p '(rust-mode rust-ts-mode))
      (flycheck-rust-setup)))

  (use-package flycheck-rust
    :ensure t
    :after flycheck
    :hook (flycheck-mode . tb/flycheck-rust-setup-maybe))
#+end_src

** Tree-sitter

Emacs 29+ has tree-sitter built in. This installs the grammars and
remaps the traditional major modes to their =-ts-mode= equivalents.

Every grammar here must have a =*-ts-mode= that something actually
reaches, or it gets downloaded and compiled for nothing. Emacs 30 has
no =elisp-ts-mode=, =make-ts-mode=, =markdown-ts-mode=, or
=scss-ts-mode=, so those grammars are out. =go=, =html=, =toml=, and
=cmake= need explicit =:mode= entries because Emacs doesn't route
their extensions to the tree-sitter mode on its own.

JavaScript uses =js-ts-mode= and the JavaScript grammar, not
=typescript-ts-mode=. Parsing JavaScript with the TypeScript grammar
is wrong, and it left =js-ts-mode= unreachable even though the LSP and
=indent-bars= hooks reference it.

=.jsx= goes to =js-ts-mode= too, on purpose. The JavaScript grammar
parses JSX natively, and the body of =js-ts-mode= re-prepends
=("\\.jsx?\\'" . js-ts-mode)= to =auto-mode-alist= every time it runs.
Point =.jsx= at =tsx-ts-mode= and it silently flips back after the
first =.js= file is opened. Agreeing with it keeps the mapping
order-independent. TypeScript keeps its own grammars: =.ts= and =.mts=
on =typescript-ts-mode=, =.tsx= on =tsx-ts-mode=.

#+begin_src emacs-lisp
  (use-package treesit
    :mode (("\\.tsx\\'" . tsx-ts-mode)
           ("\\.js\\'"  . js-ts-mode)
           ("\\.mjs\\'" . js-ts-mode)
           ("\\.cjs\\'" . js-ts-mode)
           ("\\.jsx\\'" . js-ts-mode)
           ("\\.mts\\'" . typescript-ts-mode)
           ("\\.ts\\'"  . typescript-ts-mode)
           ("\\.json\\'" .  json-ts-mode)
           ("\\.yaml\\'" .  yaml-ts-mode)
           ("\\.yml\\'" .  yaml-ts-mode)
           ("\\.go\\'" . go-ts-mode)
           ("/go\\.mod\\'" . go-mod-ts-mode)
           ("\\.cmake\\'" . cmake-ts-mode)
           ("/CMakeLists\\.txt\\'" . cmake-ts-mode)
           ("\\.Dockerfile\\'" . dockerfile-ts-mode))
    :preface
    (defconst tb/treesit-grammar-sources
      '((bash       "https://github.com/tree-sitter/tree-sitter-bash")
        (c          "https://github.com/tree-sitter/tree-sitter-c"          "v0.20.7")

        (cpp        "https://github.com/tree-sitter/tree-sitter-cpp")
        (css        "https://github.com/tree-sitter/tree-sitter-css"        "v0.20.0")
        (dockerfile "https://github.com/camdencheek/tree-sitter-dockerfile")
        (go         "https://github.com/tree-sitter/tree-sitter-go"         "v0.20.0")
        (gomod      "https://github.com/camdencheek/tree-sitter-go-mod")
        (html       "https://github.com/tree-sitter/tree-sitter-html"       "v0.20.1")
        (java       "https://github.com/tree-sitter/tree-sitter-java")
        (javascript "https://github.com/tree-sitter/tree-sitter-javascript" "v0.21.2" "src")
        (json       "https://github.com/tree-sitter/tree-sitter-json"       "v0.20.2")
        (just       "https://github.com/IndianBoy42/tree-sitter-just")
        (python     "https://github.com/tree-sitter/tree-sitter-python"     "v0.20.4")
        (ruby       "https://github.com/tree-sitter/tree-sitter-ruby")
        (rust       "https://github.com/tree-sitter/tree-sitter-rust"       "v0.24.1" "src")

    (defun tb/setup-install-grammars ()

      (interactive)

    (dolist (mapping
             '((bash-mode . bash-ts-mode)

               (conf-toml-mode . toml-ts-mode)
               (css-mode . css-ts-mode)
               (dockerfile-mode . dockerfile-ts-mode)
               (html-mode . html-ts-mode)
               (java-mode . java-ts-mode)
               (js-json-mode . json-ts-mode)
               (javascript-mode . js-ts-mode)
               (js-mode . js-ts-mode)
               (js2-mode . js-ts-mode)
               (json-mode . json-ts-mode)
               (mhtml-mode . html-ts-mode)
               (python-mode . python-ts-mode)
               (sh-base-mode . bash-ts-mode)
               (sh-mode . bash-ts-mode)

** LSP

I use LSP for most languages. [[https://github.com/blahgeek/emacs-lsp-booster][emacs-lsp-booster]] wraps the server when
it's on =PATH= to speed up JSON parsing.

#+begin_src emacs-lisp
  (use-package lsp-ui
    :ensure t
    :after lsp-mode
    :commands lsp-ui-mode
    :hook (lsp-mode . lsp-ui-mode)
    :config
    (setq lsp-ui-doc-enable nil))

  (use-package lsp-mode
    :ensure t
    :commands (lsp lsp-deferred)
    :hook ((tsx-ts-mode typescript-ts-mode js-ts-mode python-ts-mode java-ts-mode) . lsp-deferred)
    :init
    (setq lsp-use-plists t)
    (setq lsp-enable-dap-auto-configure nil)
    ;; Corfu consumes lsp-mode's capf itself; :none stops lsp-mode from
    ;; configuring company. lsp-mode pins lsp-capf to the lsp-passthrough
    ;; style in completion-category-defaults; the lsp-capf entry in
    ;; completion-category-overrides (Orderless block) takes precedence.
    (setq lsp-completion-provider :none)
    :config
    (defun lsp-booster--advice-json-parse (old-fn &rest args)
      (or
       (when (equal (following-char) ?#)
         (let ((bytecode (read (current-buffer))))
           (when (byte-code-function-p bytecode)
             (funcall bytecode))))
       (apply old-fn args)))

    (defun lsp-booster--advice-final-command (old-fn cmd &optional test?)
      (let ((orig-result (funcall old-fn cmd test?)))
        (if (and (not test?)
                 (not (file-remote-p default-directory))
                 lsp-use-plists
                 (not (functionp 'json-rpc-connection))
                 (executable-find "emacs-lsp-booster"))
            (progn
              (when-let ((resolved (executable-find (car orig-result))))
                (setcar orig-result resolved))
              (message "Using emacs-lsp-booster for %s!" orig-result)
              (cons "emacs-lsp-booster" orig-result))
          orig-result)))

    (advice-add (if (fboundp 'json-parse-buffer) 'json-parse-buffer 'json-read)
                :around #'lsp-booster--advice-json-parse)
    (advice-add 'lsp-resolve-final-command :around #'lsp-booster--advice-final-command))
#+end_src

** Nix

=C-c C-f= lives in the =nix-mode= block, not the =nixfmt= one. Bound
under =use-package nixfmt=, it would wait for nixfmt to load, and
nixfmt only loads when the binding is pressed. It would never get
installed. Hanging it off nix-mode installs it when nix-mode loads,
and nixfmt's autoload pulls the package in on first use.

#+begin_src emacs-lisp
  (use-package lsp-nix
    :ensure lsp-mode
    :after (lsp-mode)
    :custom
    (lsp-nix-nil-formatter ["nixfmt"]))

  (use-package nixfmt
    :ensure t
    :commands (nixfmt-buffer nixfmt-region))

  (use-package nix-mode
    :ensure t
    :bind (:map nix-mode-map
                ("C-c C-f" . nixfmt-buffer))
    :hook (nix-mode . lsp-deferred))
#+end_src

lsp-java drags in treemacs through lsp-treemacs, and loading treemacs
logs "Python3 not found" when there's no python3. I never use the

#+end_src

I only want DAP for Java, but lsp-mode turns on
=dap-auto-configure-mode= in every LSP buffer as soon as dap-mode is
installed, and lsp-java depends on it. So it's off globally in the
lsp-mode block and back on buffer-locally here, before =lsp=
configures the buffer.

#+begin_src emacs-lisp
  (defun my/lsp-java-enable-dap ()
    (setq-local lsp-enable-dap-auto-configure t))

  (add-hook 'java-ts-mode-hook #'my/lsp-java-enable-dap)
#+end_src

DAP's =tooltip= feature binds =[mouse-movement]= in =lsp-mode-map= to
a handler that calls =x-hide-tip=. That C function doesn't exist in
no-GUI builds, so every mouse move under =xterm-mouse-mode= logs
"Symbol's function definition is void: x-hide-tip". Drop the feature
on those builds.

#+begin_src emacs-lisp
  (use-package dap-mode
    :defer t
    :config
    (unless (fboundp 'x-hide-tip)
      (setq dap-auto-configure-features
            (delq 'tooltip dap-auto-configure-features))))
#+end_src
